## 简介
本指南面向希望为 DeepSeek-GUI（Kun）贡献代码、文档与问题的开发者，提供从 Fork 仓库到发起 Pull Request 的完整流程说明；同时给出编码规范、提交流程、文档贡献方式、测试要求、Issue 报告规范、开发环境搭建步骤以及社区行为准则与沟通渠道。目标是让不同背景的贡献者都能高效、高质量地参与协作。

## 项目结构
本项目采用多工作区与分层组织：
- 根目录包含 Electron GUI 应用、脚本与配置
- src 下分为 main、preload、renderer、shared 等模块
- kun 子工程提供运行时与 CLI
- docs 存放用户与开发者文档
- scripts 包含构建、发布、校验与冒烟测试脚本
- packages 包含扩展相关包

## 详细组件分析

### 贡献流程（Fork、分支、提交、PR）
- Fork 仓库并在本地克隆
- 切换到 develop 并同步最新变更
- 从 develop 创建短期功能分支（如 feat/short-description）
- 在本地完成实现与验证（类型检查、构建、测试、开发运行）
- 推送分支并发起指向 develop 的 PR
- 根据评审意见迭代，直至通过检查并获得批准
- 由维护者合并至 develop；稳定版本由维护者从 develop 合入 master

```mermaid
flowchart TD
Start(["开始"]) --> Sync["同步 develop"]
Sync --> Branch["创建功能分支"]
Branch --> Implement["实现与本地验证"]
Implement --> Check{"校验通过?"}
Check -- 否 --> Fix["修复问题并重跑校验"]
Fix --> Check
Check -- 是 --> Push["推送分支并开 PR"]
Push --> Review["代码评审"]
Review --> Iterate{"需要修改?"}
Iterate -- 是 --> Fix
Iterate -- 否 --> Merge["合并至 develop"]
Merge --> End(["结束"])
```

### 代码规范（风格、命名、注释、类型）
- 代码风格与规则：使用 ESLint + TypeScript ESLint，忽略构建产物与依赖目录；对 React Hooks 启用规则；关闭部分过于严格的规则以保持可读性。
- 类型系统：TypeScript 为主，通过 tsc 进行类型检查；确保跨平台一致性与可维护性。
- 命名约定：遵循现有项目结构与命名方式，保持统一与清晰。
- 注释规范：以可读性优先，避免过度注释；复杂逻辑应补充必要说明。
- 安全与隐私：禁止提交密钥、Token、API Key 或机器特定路径。

### 测试要求（新增测试、覆盖率、环境配置）
- 测试框架：Vitest，配置文件定义别名、环境与测试范围。
- 命令：npm run test 运行全部测试；npm run test:kun 运行运行时测试；npm run test:watch 监听模式。
- 环境：Node 环境，禁用系统凭据存储以便测试稳定性；Windows 下限制并发与超时。
- 覆盖率：当前仓库未显式配置覆盖率阈值，建议在涉及逻辑变更时补充单元测试并确保通过。

## 性能考虑
- 测试并发与超时：Windows 平台限制最大工作进程数并延长超时，以提升稳定性。
- 构建产物：避免将构建输出与依赖纳入源码检查；使用忽略规则减少噪音。
- 资源与内存：大型任务建议使用后台 Shell、子代理与计划机制，避免阻塞主线程。

## 故障排查指南
- 类型检查失败：检查 TypeScript 配置与依赖版本，确保 tsc 无错误。
- 构建失败：确认 Node 版本满足要求，清理缓存后重试；检查脚本依赖是否安装完整。
- 测试失败：查看 Vitest 输出，定位断言与环境问题；必要时增加调试日志。
- 开发运行异常：检查端口占用、权限与模型 Provider 配置；参考日志路径定位问题。
- Issue 日志收集：按模板提供操作系统、版本、复现步骤、期望与实际行为、日志与截图。

## 简介
Kun 是一款本地优先的 AI Agent 工作台，将 Code、Write、Design、Research 和 Automate 整合在同一运行时中，并通过桌面 GUI 与终端 TUI 共享同一后台服务。它强调“从需求到验收”的连续工作流：澄清需求、探索方案、制定计划、执行任务、审查测试、交付结果，所有过程可观察、可控制、可回溯。

- 适合人群：开发者、写作者、设计师、研究人员以及需要自动化重复工作的个人与团队。
- 工作方式：GUI 用于可视化观察与交互；TUI 保持手不离键盘；两者通过同一个 `kun serve` 共享线程、计划、审批、模型连接与任务记录。
- 模式选择：简单任务用 Direct 模式；跨文件、跨阶段、可明确验收的复杂任务使用实验性的 Agent Graph。

## 项目结构
Kun 采用“单运行时 + 多客户端”的结构：渲染层（GUI/TUI）通过 HTTP/SSE 边界调用后端 `kun serve`，后者提供线程、事件、审批、用量、工作区等能力。Graph 编排、Agent 治理、恢复机制均在该边界内实现。

## 核心组件
- 真实项目工作台：本地工作区、文件搜索与编辑、Terminal、Browser、Git/Worktree、内联 Diff 与 Changes 面板。
- 长任务与上下文管理：Plan、Todo、持久目标、会话压缩、分叉、归档、旁支问题、后台 Shell 与子代理。
- 模型与额度管理：统一入口管理订阅、套餐与 API；按默认 Agent、线程、Design、Write、Schedule 或子代理选择模型。
- Agent 与知识管理：Agent Profile、长期记忆、项目级 AGENTS.md、Skills、MCP 与 Extensions。
- 自动化与开放扩展：一次性或周期性 Schedule、可视化 Loop、Hook、本地运行 API，以及可安装或侧载的 `.kunx` 扩展。
- 多模态与安全：图片和 PDF 输入、视觉理解、媒体生成、Sandbox、工具审批、Computer Use 权限与敏感操作确认。

## 架构总览
Kun 的工作流由“界面 → 桥接 → 运行时”构成，所有工作区（Code、Write、Design、Research、Automate）都通过统一的 HTTP/SSE 边界访问线程、事件、审批、用量与工作区能力。Graph 模式作为每轮任务的编排策略，不引入第二套运行时。

```mermaid

participant G as "GUI/TUI"
participant P as "Preload/Main"
participant S as "kun serve"
participant M as "模型Provider"
U->>G : 发送任务/指令
G->>P : runtimeRequest / startSse
P->>S : POST /v1/threads/{id}/turns
S->>M : 调用模型(文本/图片/视频)
M-->>S : 返回响应/流式片段
S-->>P : SSE 事件(文本/工具/子代理/审批)
P-->>G : 更新UI/状态
G-->>U : 展示结果/下一步动作
```

## 详细组件分析

### 工作区一：Code（AI 编程与审查）
- 能力：在真实代码库上搜索、编辑文件、执行命令、管理 Plan/Todo、查看 Diff 与测试结果、发起 Review。
- 场景：Bug 修复、功能开发、重构、代码审查、发布前验证。
- 交付：代码改动、测试结果、实施计划、Review findings。
- 集成：与 Design 工作区的“实现为代码”双向打通；与 Write 共享模型与审批；与 Automate 共享 Schedule/Loop/MCP。

### Direct 模式 vs Agent Graph 模式
- Direct 模式：单点修改、简单问答、短任务更快更直接。
- Agent Graph 模式：跨文件、跨阶段、可明确验收的复杂任务；Lead Agent 建立依赖图，派发受限子代理，持续监督与验收，最终交付。
- 适用建议：轻量任务选 Direct；需要并行分工、依赖关系、持续监督和明确验收的任务选 Graph。

### GUI 与 TUI 共享运行时
- 共享内容：线程、回合、审批、结构化输入、事件序列号、用量、模型连接。
- 启动方式：GUI 与 TUI 各自独立，但连接到同一 `kun serve`；关闭一个不影响其他客户端或后台任务。
- 安全与重连：发现仅接受回环地址，校验实例 ID/PID/版本；断线重连后基于游标回放事件。

## 依赖关系分析
- 运行时边界：GUI/TUI 通过 Preload/Main 转发至 `kun serve` 的 HTTP/SSE 接口，避免在渲染层实现 Agent 业务逻辑。
- 配置与能力：Kun 运行时设置集中管理模型、审批、沙箱、工具输出限制、上下文压缩、存储、调试、图像/语音/视频生成、质量、Graph、Lab 等。
- Provider 预设：内置 DeepSeek、小米、MiniMax、智谱 Coding Plan、Z.ai Coding Plan、Kimi、Moonshot CN/Global 等，支持自定义兼容端点。

## 性能考量
- 缓存命中优化：稳定系统提示前缀、工具 schema 规范化、历史消息修复、只读工具并发批处理、累计计数器恢复。
- 冷启动命中率较低，热启动后可稳定超过 90%。
- 动态上下文必须追加在稳定前缀之后，避免破坏缓存指纹。
- 大工具结果需做 token 有界或标记化处理，防止日志膨胀。

## 故障排查指南
- Graph 诊断：使用 `/v1/graphs/diagnostics` 获取脱敏聚合信息，定位创建失败、阻塞节点、写入冲突、日志损坏等问题。
- 运行时状态：通过 `kun runtime status/restart/stop` 检查服务健康；确保 GUI 与 TUI 指向同一数据目录。
- 权限与审批：工具调用与敏感操作需经审批；若卡住，检查审批队列与沙箱策略。
- 重连与会话：断线重连后基于最新序列号回放事件；若出现悬挂审批/输入，检查是否已被其他客户端处理。

## 结论
Kun 以“单运行时 + 多客户端”的架构，将 Code、Write、Design、Research、Automate 统一到一条可追溯的工作流中。Direct 模式满足轻量任务，Agent Graph 模式支撑复杂分工与验收。GUI 与 TUI 共享运行时，既保证一致性又兼顾不同使用习惯。配合 Provider 预设、模型与额度管理、知识与扩展生态，Kun 能够覆盖从想法到交付的全链路需求。

## 附录：使用示例与演示
- 快速开始：下载桌面版，选择语言、登录模型或配置 API Key、打开本地项目并发送清晰且可验证的任务。
- 工作区演示：
  - Code：在工作区中搜索代码、编辑文件、执行命令、查看 Diff 与测试结果。
  - Write：在写作空间撰写与润色，导出为 Markdown/HTML/PDF/DOCX/PPTX。
  - Design：在画布中描述 UI，生成 HTML 原型并实时预览，迭代后“实现为代码”。
  - Research：上传 PDF/图片，提取证据并整理结论，形成后续任务。
  - Automate：配置 Schedule/Loop/Hook，运行可视化工作流，查看执行历史与证据。
- 模式切换：简单任务使用 Direct；复杂任务切换到 Graph，建立依赖图、委派子代理、监督与验收。
- 共享运行时：同时打开 GUI 与 TUI，它们共享线程、计划、审批与用量；可在任一界面继续同一任务。

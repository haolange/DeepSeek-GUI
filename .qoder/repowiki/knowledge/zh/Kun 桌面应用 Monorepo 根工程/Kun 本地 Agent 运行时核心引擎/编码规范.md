- 对外稳定契约集中在 `contracts/` 并通过 Zod schema 校验，所有 HTTP/SSE 请求/响应都经由该层类型推导，避免在业务层散落原始 JSON。
- 上层模块通过 `ports/` 中定义的接口（如 ModelClient、ToolHost、ThreadStore）进行依赖注入，具体实现放在 `adapters/` 或 `in-memory-*` 文件中，便于单元测试替换。
- 每个功能模块配套同名 `.test.ts` 文件置于同一目录下，测试命名采用 `<feature>.test.ts` 形式，并按场景拆分为多个测试文件（如 `compat-model-client.*.test.ts`）。
- 持久化采用 JSONL 追加日志 + 原子写入元数据（index.json、thread.json、session.json）的模式，允许损坏行被跳过以保证可恢复性。
- 配置解析遵循固定优先级：内置默认值 → JSON 配置文件 → 环境变量 → CLI 参数，并通过 `config/` 下的 KunConfig/ProjectConfig 统一合并。
- 能力开关以显式 feature flag 形式出现在 `capabilities.*` 配置段（如 mcp/web/skills/memory/subagents/attachments），未启用时对应工具/端点不可见且不会初始化后端。

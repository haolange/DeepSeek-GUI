模块以 `src/index.ts` 为单一包入口，按职责划分为清晰的分层：
- `contracts/` 定义 Zod 校验的 HTTP/SSE 契约类型（threads、turns、items、events、approvals、usage、graph 等），是对外稳定 API 的唯一来源。
- `domain/` 实现领域实体（Thread、Turn、Item、Event、Approval、Usage、Session）及事件归约器，不依赖外部端口。
- `ports/` 声明抽象接口（ModelClient、ToolHost、ThreadStore、SessionStore、EventBus、ApprovalGate、UserInputGate、WebProvider、WorkspaceInspector 等），作为上层业务与下层实现的解耦边界。
- `adapters/` 提供具体实现：`model/` 下兼容 DeepSeek/Gemini/Claude 等多模型的 ModelClient 适配器、路由池、重试策略与流解码；`file/`、`hybrid/`、`in-memory-*` 多种 Thread/Session 存储后端；`tool/` 内置 bash、git、lsp、read、browser-use、computer-use 等工具提供者；`workspace/` 工作区检查器。
- `loop/` 是缓存优先的 Agent 主循环：上下文压缩、历史修复、模型请求组合、工具调度、轮次预算与中断、SSE 事件收集。
- `services/` 编排级服务：ThreadService、TurnService、UsageService、Extension* 系列服务、OAuth/Quota/Migration 等横切能力。
- `server/` 基于 Hono 的 HTTP+SSE 服务器，暴露 `/v1/*` REST 路由，负责认证、SSE 回放、运行时发现与恢复。
- `cli/`、`tui/`、`graph/`、`delegation/`、`extensions/`、`hooks/`、`skills/`、`cache/`、`telemetry/`、`manager/`、`memory/`、`security/`、`prompt/`、`quality/`、`reliability/`、`review/`、`supplychain/`、`tasks/`、`benchmark/`、`attachments/`、`artifacts/` 等子目录分别承担 CLI 入口、TUI、图编排、子代理委派、扩展宿主、钩子系统、技能、缓存、遥测、进程管理、内存、安全、提示词、质量规则、操作日志、审查、供应链审计、任务图、基准测试、附件与工件等横向能力。
依赖方向自顶向下：server/cli/tui → services → loop → adapters/ports → domain/contracts；contracts 与 domain 无向上依赖，保证契约稳定。构建产物通过 `package.json` 的 `exports` 字段将 contracts/domain/ports/adapters/services/hooks/loop/server/tui/cache/telemetry 等子路径单独导出，供 GUI 主进程与其他包引用。

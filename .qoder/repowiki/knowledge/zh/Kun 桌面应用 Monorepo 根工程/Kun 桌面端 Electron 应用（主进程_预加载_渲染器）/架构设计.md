模块按 Electron 三进程模型组织：
- `src/main/index.ts` 作为主进程入口，在 `app.whenReady` 前完成身份配置、单实例锁、旧数据迁移（`legacy-data-migration`、`runtime-data-dir-migration`）、安全加固（`browser-security/web-contents-hardening`），随后注册托盘、窗口、SSE IPC、各子运行时（Claw/Schedule/Daemon/Workflow/Telegram/Weixin Bridge）并挂载 `services/*`（工作区、Git、技能、UI 插件、语音转文本等）。
- `src/preload/index.ts` 通过 `contextBridge.exposeInMainWorld('kunGui', ...)` 暴露统一 API，所有对主进程的调用均走 `ipcRenderer.invoke/on`，并按功能域分组（settings、workspace、extension、workflow、browser-use、computer-use、terminal 等）。
- `src/renderer/src/main.tsx` 为 React 应用启动点，根据 URL 参数动态加载 StorageRelocationBootView / RuntimeMigrationRecoveryView 或主 App；UI 通过 `window.kunGui` 调用预加载层。
- `src/shared/*` 是主进程与渲染器共享的类型、设置图（`app-settings-graph.ts`）、协议契约（`extension-ipc.ts`、`kun-gui-api.ts`、`tray-provider-quota.ts` 等），被三方共同 import。
- 子目录按职责划分：`main/ipc` 集中注册 app/extension IPC handler 及 JSON Schema 校验；`main/extensions` 实现扩展描述符解析、资源/媒体协议、view session 与安全守卫；`main/runtime` 封装 Kun 运行时适配器、健康监控、配置服务与关闭协调器；`main/services` 提供文件、Git、工作区、导出等业务能力；`main/data-migration`、`main/storage-relocation`、`main/uninstall`、`main/terminal`、`main/browser-use`、`main/computer-use` 各自独立成子系统。
- 依赖方向单向：renderer → preload → main → shared；测试文件以 `.test.ts` 与源码同目录配对，使用 fixtures（如 `__fixtures__/runtime-data-migration`、`shared/__fixtures__/data-migration`）。
